## P0

### [P0 · Critical · OPEN] `packages/core/src/lib/application/application.ts:37`

**Status:** OPEN

**Bug:** `Application.init` defaults `bodyParser` to `false` and `main.ts` does not override it, so Nest never mounts JSON/urlencoded parsers; `POST /auth/signin` and `POST /auth/signup` see an empty body (local strategy 401 / DTO validation 400) on the normal client path.

**Fix:** Default `bodyParser` to `true` (or pass `bodyParser: true` from `main.ts`) and keep a dedicated raw-body parser only on routes that need it.

### [P0 · High · OPEN] `apps/parishbooks-svc/src/modules/auth/auth.controller.ts:29`

**Status:** OPEN

**Bug:** Controller routes are `POST auth/signin` and `POST auth/signup`, but `@parishbooks/api-sdk` (and `apps/parishbooks-ui/src/actions/auth/sign-in.action.ts`) call `/api/v1/auth/sign-in` and `/api/v1/auth/sign-up`; official clients 404 even when the handlers are correct.

**Fix:** Rename the controller paths to `sign-in` / `sign-up` (or regenerate the SDK from this OpenAPI) so both sides share one URL, and add a contract test that hits the SDK paths.

## P1

### [P1 · High · OPEN] `apps/parishbooks-svc/src/modules/auth/auth.controller.ts:41`

**Status:** OPEN

**Bug:** Sign-in puts `accessToken` and `refreshToken` in the JSON body while also setting httpOnly cookies; any XSS (or a server action that returns `data` to the browser) can steal the refresh token and defeats the cookie hardening.

**Fix:** Return only `redirectTo` (and maybe non-secret user fields) from sign-in; keep tokens exclusively on `httpOnly` cookies, and stop forwarding token fields through UI server actions.

### [P1 · High · OPEN] `apps/parishbooks-svc/src/modules/auth/strategies/jwt.strategy.ts:27`

**Status:** OPEN

**Bug:** Access-token validation is fail-open on missing `typ` (`if (payload.typ && payload.typ !== 'access')`); refresh tokens minted by the previous `SignInService.mintJwt` have no `typ`, embed the full user, and live 7–30 days, so they are accepted as access tokens.

**Fix:** Require `payload.typ === JWT_TOKEN_TYPE_ACCESS` (reject missing `typ`) and rotate any pre-`typ` refresh cookies off at refresh time.

### [P1 · High · OPEN] `apps/parishbooks-svc/src/modules/auth/services/signup.service.ts:33`

**Status:** OPEN

**Bug:** Sign-up always creates `emailVerified: false` and returns `/verify-email`, while `SignInService.validateUser` rejects unverified users and this controller has no verify/OTP route; a new user cannot complete sign-in.

**Fix:** Add the verify-email (OTP) endpoints the SDK already describes, or persist `emailVerified: true` only if product policy is to skip verification.

### [P1 · High · OPEN] `apps/parishbooks-svc/src/modules/auth/services/token.service.ts:47`

**Status:** OPEN

**Bug:** `refreshAccessToken` uses a bare `catch` that maps every failure—including `UserBannedException`, `EmailNotVerifiedException`, and database errors—to `RefreshTokenInvalidException` (401), so banned/unverified refresh is indistinguishable from a bad cookie and outages look like auth failures.

**Fix:** Re-throw known `HttpException`s (or catch only `JsonWebTokenError` / `TokenExpiredError`) and let infrastructure errors surface as 500.

### [P1 · High · OPEN] `apps/parishbooks-svc/src/modules/auth/services/cookie.service.ts:37`

**Status:** OPEN

**Bug:** Cookie auth has no sign-out handler; `clearAuthCookies` is unused while the SDK still calls `POST /api/v1/auth/sign-out`, so clients cannot revoke the refresh cookie and a stolen refresh token stays valid for 7–30 days.

**Fix:** Add `POST /auth/sign-out` that clears both auth cookies (and, if you add a denylist/family later, revoke the refresh `jti`).

## P2

### [P2 · Medium · OPEN] `apps/parishbooks-svc/src/modules/auth/auth.controller.ts:36`

**Status:** OPEN

**Bug:** Sign-in binds only `@Req()`, so the global `ValidationPipe` never applies `SignInDto`; `rememberMe` is used as a truthy flag, and the string `"false"` (or any non-empty value) mints a 30-day refresh token and cookie.

**Fix:** Add `@Body() body: SignInDto` (keep `@Req()` for `user`) and pass `body.rememberMe` after `transform` + `@IsBoolean()`.

### [P2 · Medium · OPEN] `apps/parishbooks-svc/src/modules/auth/strategies/jwt.strategy.ts:26`

**Status:** OPEN

**Bug:** After sign-in, `JwtStrategy.validate` never reloads the user, so a ban or email-unverify does not take effect until the 1-day access JWT expires; only refresh re-checks, and that path currently swallows the 403 (see token.service catch).

**Fix:** Load the user (or at least `banned` / `emailVerified`) in `JwtStrategy.validate` and reject with the same exceptions as sign-in, or shorten access TTL and keep the check on refresh without swallowing 403.

### [P2 · Medium · OPEN] `apps/parishbooks-svc/src/modules/auth/repository/auth.repository.ts:11`

**Status:** OPEN

**Bug:** Sign-up uniqueness is check-then-insert on email only, while the schema unique key is `(tenantId, email)` and each sign-up creates a new tenant; two concurrent sign-ups of the same email can both pass `checkUserExists` and persist duplicate accounts.

**Fix:** Add a unique index on `user.email` (if emails are globally unique) and treat the unique-violation as `UserAlreadyExistsException` inside the transaction.

### [P2 · Medium · OPEN] `apps/parishbooks-svc/src/modules/auth/auth.controller.ts:29`

**Status:** OPEN

**Bug:** Nest `@Post()` defaults to HTTP 201; sign-in and refresh document `@ApiOkResponse` (200) and the generated SDK types those responses as `200`, so OpenAPI/SDK status maps are wrong even though hey-api treats any 2xx as success today.

**Fix:** Add `@HttpCode(200)` on sign-in and refresh (or document 201 consistently) and regenerate the SDK.

## P3

### [P3 · Low · OPEN] `apps/parishbooks-svc/src/modules/auth/services/password.service.ts:8`

**Status:** OPEN

**Bug:** `hash()` returns the input unchanged when it looks like a bcrypt string; a user who chooses such a password at sign-up cannot sign in because `compare` will hash that string again instead of treating it as the plaintext.

**Fix:** Always `bcrypt.hash` the submitted password; never detect-and-skip on the plaintext.
