## P1

### [P1 · High · FIXED] `apps/parishbooks-svc/src/modules/auth/services/verification.service.ts:34-44`

**Status:** FIXED

**Bug:** `verifyEmailOtp` sets `user.status` to `ACTIVE` for any non-deleted user with a valid OTP, including admin-`SUSPENDED` accounts, so suspension can be cleared without an admin action.

**Fix:** Before OTP verification (or before `markEmailVerified`), reject `UserStatus.SUSPENDED` with `UserBannedException` (or a dedicated suspended error); only allow `PENDING` → `ACTIVE` on this path.

**Resolved:** 2026-10-13 — Reject `SUSPENDED` in `verifyEmailOtp`; `markEmailVerified` only when status is `PENDING`, inside a DB transaction with OTP consumption.

### [P1 · High · FIXED] `apps/parishbooks-svc/src/modules/auth/helpers/auth-user.helper.ts:13-21`

**Status:** FIXED

**Bug:** `toAuthUser` always sets `banned: false` and derives `emailVerified` only from `ACTIVE`, so `SUSPENDED` users hit `EmailNotVerifiedException` on sign-in/refresh instead of a ban/suspend response, and no code path treats suspension as a distinct auth state.

**Fix:** Map `UserStatus.SUSPENDED` to `banned: true` (or a dedicated flag), keep `emailVerified` accurate, and ensure `SignInService.validateUser` rejects suspended users with `UserBannedException` before the unverified check.

**Resolved:** 2026-10-13 — `banned: user.status === UserStatus.SUSPENDED`; existing `validateUser` ban check runs before email verification.

## P2

### [P2 · Medium · FIXED] `apps/parishbooks-svc/src/modules/auth/services/verification.service.ts:21-31`

**Status:** FIXED

**Bug:** `sendEmailVerificationOtp` sends OTPs to `SUSPENDED` users (only skips `ACTIVE`), enabling the verify endpoint abuse above and confusing UX for banned accounts.

**Fix:** Skip send (and verify) when `user.status === UserStatus.SUSPENDED`; restrict resend to `PENDING` (and optionally other pre-active states if added later).

**Resolved:** 2026-10-13 — Send only when `user.status === UserStatus.PENDING`; password-reset send skips `SUSPENDED`.

### [P2 · Medium · FIXED] `apps/parishbooks-svc/src/modules/auth/services/verification.service.ts:13-82`

**Status:** FIXED

**Bug:** OTP send cooldown (`lastSendAtByCooldownKey`) is an in-process `Map`, so rate limits reset per instance and are bypassed under horizontal scale or process restarts.

**Fix:** Enforce cooldown in Postgres (e.g. `verification.updated_at` / dedicated row) or a shared store (Redis), matching production deployment expectations.

**Resolved:** 2026-10-13 — Cooldown uses existing `verification.updated_at` via `findByIdentifier` before upsert; removed in-memory map.

### [P2 · Medium · FIXED] `apps/parishbooks-svc/src/modules/auth/services/verification.service.ts:39-43`

**Status:** FIXED

**Bug:** OTP consumption (`verifyOtpChallenge` deletes the row) and `markEmailVerified` are not in one transaction; if the update fails after OTP delete, the user loses the code but stays `PENDING`.

**Fix:** Run OTP verify + `user.status` update in a single DB transaction (or verify OTP only after a successful status update using a conditional update pattern).

**Resolved:** 2026-10-13 — `DataSource.transaction` wraps OTP verify and `markEmailVerified`; repository/OtpHelper accept optional `EntityManager`.

### [P2 · Medium · FIXED] `apps/parishbooks-svc/src/modules/auth/auth.service.ts:16-21`

**Status:** FIXED

**Bug:** `validateJwtPayload` passes `payload.roles` from the JWT into `toAuthUser` without loading roles from the database, so any future role claims in access tokens would be client-trusted once minted.

**Fix:** Omit roles from the signed access token until sourced from `member` (or load roles in `validateJwtPayload` and ignore JWT `roles` entirely).

**Resolved:** 2026-10-13 — JWT validation uses `toAuthUser(user)` only; access tokens mint explicit claims without `roles`.

### [P2 · Medium · FIXED] `apps/parishbooks-svc/src/modules/auth/services/token.service.ts:33-36`

**Status:** FIXED

**Bug:** Refresh tokens are not rotated on `/auth/refresh`; a stolen refresh cookie remains valid until expiry (`7d` / `30d`).

**Fix:** Issue a new refresh token on each refresh, persist/revoke family server-side if required, and clear old cookie when rotating.

**Resolved:** 2026-10-13 — `/auth/refresh` mints a new refresh token and rewrites both auth cookies (cookie rotation; no server-side refresh family store yet).

**Status:** FIXED

**Bug:** `updateCredentialPassword` uses `profile.update` without checking affected rows; a missing profile (data corruption or partial signup) fails silently and password reset appears successful.

**Resolved:** 2026-10-13 — Throws `UserNotFoundException` when update affects zero rows.

### [P3 · Low · FIXED] `apps/parishbooks-svc/src/modules/auth/dto/signin.dto.ts:10-13`

**Status:** FIXED

**Bug:** Sign-in `email` is validated as `@IsString()` only, unlike other auth DTOs that use `@IsEmail()`, so obviously malformed emails reach Passport before normalization (inconsistent errors vs sign-up Zod `z.email()`).

**Fix:** Add `@IsEmail()` (or normalize in a pipe) for consistent 400 responses at the boundary.

**Resolved:** 2026-10-13 — Added `@IsEmail()` on `SignInDto.email`.
